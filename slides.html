1. Por que NÃO chamar o LLM direto do Front-End?

Segurança & Regra de Ouro

❌ Se a chamada fosse no Front-End:

  • Vazamento fatal da API Key: Qualquer usuário abre o DevTools (F12) e copia sua chave.
  • Alto Acoplamento: O front-end fica dependente das regras e formato daquela empresa específica.
  • Sem Controle de Custos: Qualquer pessoa pode disparar milhares de requisições no seu cartão.

✅ Solução com Back-End Intermediário:

  • Chave 100% Segura: Fica guardada no arquivo .env no servidor.
  • Baixo Acoplamento: O navegador só fala com o nosso servidor via JSON simples.
  • Injeção do System Prompt: O servidor define a personalidade e regras sem o usuário adulterar.

2. Arquitetura do Sistema Distribuído

O Fluxo de Comunicação em 3 Nós

Nossa aplicação é um sistema distribuído dividido em 3 partes independentes:

1. Navegador (Cliente)
index.html
Interface visual simples
➡️
2. Servidor (Back-End)
server.js (Node/Express)
Protege a chave + System Prompt
➡️
3. Provedor de LLM (Nuvem)
Google Gemini / OpenAI
Processa a inteligência

📌 Protocolo: HTTP REST com formato de dados JSON. O front-end envia { message: "..." } e recebe { reply: "...", provider: "..." }.

3. O Front-End: Simples e Desacoplado

index.html

O front-end é minimalista: ele não sabe o que é Gemini ou GPT. Ele apenas faz um fetch para a rota /api/chat:

// O Front-End envia a mensagem digitada pelo usuário via POST
const resposta = await fetch('/api/chat', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ message: mensagemDoUsuario })
});

const dados = await resposta.json();
// Exibe a resposta recebida na tela
adicionarMensagem(dados.reply, 'bot', dados.provider);

💡 Por que isso é bom? Se mudarmos de provedor amanhã, o código do front-end não muda nem uma linha!

4. O Back-End: O Guardião Seguro

server.js (Node.js + Express)

🛡️ Responsabilidades do Back-End:

  • Recebe o POST /api/chat vindo do navegador.
  • Lê a chave secreta com segurança via dotenv (.env).
  • Junta a mensagem do usuário com o System Prompt.
  • Chama a API do LLM com a chave protegida.
  • Entrega a resposta limpa para o usuário.
// No server.js:
const apiKey = process.env.GEMINI_API_KEY;

// Faz a requisição protegida para a nuvem
const response = await fetch(urlComKey, {
  method: 'POST',
  body: JSON.stringify({
    system_instruction: { parts: [{ text: SYSTEM_PROMPT }] },
    contents: [{ parts: [{ text: message }] }]
  })
});

5. O que é o System Prompt?

Definindo a personalidade e regras da IA

O System Prompt são as instruções que o modelo recebe antes de começar a conversa. Ele orienta tom de voz, regras e limites:

const SYSTEM_PROMPT = `Você é um assistente acadêmico amigável e didático 
na aula de Desenvolvimento Web do professor Renato. 
Responda de forma clara, objetiva, bem-humorada e sempre em português brasileiro. 
Mantenha respostas curtas (máximo 2 a 3 parágrafos).`;

🔒 Por que fica no Back-End?

Se ficasse no front-end, qualquer usuário poderia inspecionar e alterar as instruções ou fazer "Prompt Injection".

🎯 Benefício Prático

Garante que a IA sempre atue como tutor da matéria, sem se desviar do propósito acadêmico.

6. Desacoplamento: Troca de Provedor

Mudando apenas 1 linha no server.js!

Em sistemas distribuídos modernos, nunca devemos ficar "presos" a um único fornecedor (Vendor Lock-in):

// No server.js - Basta alterar esta linha ou no arquivo .env:
const PROVIDER = 'gemini';   // ✅ Chamada real ao Google Gemini
// const PROVIDER = 'openai';   // 🤖 Troca para OpenAI (gpt-4o-mini)
// const PROVIDER = 'anthropic';// 🧠 Troca para Claude (Anthropic)

✨ O Grande Aprendizado do Grupo 4:

O front-end (index.html) não sofreu nenhuma alteração! O contrato da API interna (/api/chat) continua idêntico. Isso é a essência de uma arquitetura limpa e de baixo acoplamento.
